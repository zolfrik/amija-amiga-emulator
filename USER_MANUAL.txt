===============================================================================
 1.  ABOUT AMIJA
===============================================================================

  AmiJa is an Amiga 500 emulator written entirely in Java. It reproduces the
  machine at the cycle level: the CPU, the custom chips (Agnus, Denise, Paula),
  the two CIAs and the floppy drives all advance on the same 7.09 MHz master
  clock as the real hardware, so DMA arbitration, blitter timing, copper waits
  and disk bitstreams behave the way they do on an A500.

  What you get:

    *  OCS and ECS chipsets, PAL and NTSC video
    *  Chip / Slow / Fast RAM configurations, up to four floppy drives
    *  ADF, IPF (copy-protected originals) and ZIP disk sets
    *  Hard disk images (.hdf) through a Zorro II AutoConfig controller
    *  WHDLoad archives (.lha) started automatically, with no manual install
    *  Software or OpenGL rendering, with RetroArch (.glslp) CRT shaders
    *  Save states, screenshots, real joysticks, floppy drive sounds
    *  Remote play: a second player joins over the network and takes a game
       port, without needing a Kickstart or a copy of the game
    *  An automatic mode that builds the machine around whatever you load, so
       there is nothing to configure before playing

  Everything is driven from one configuration file, amiga.properties, which can
  be edited by hand or - more comfortably - from the popup that opens with F12
  while the emulator is running. This manual describes both.


===============================================================================
 2.  GETTING STARTED
===============================================================================

  With no Kickstart configured AmiJa still starts: it falls back to a built-in
  ROM of its own - original firmware written for this project and free to
  redistribute, which is why it can be shipped at all. It boots floppy games
  whose boot block loads the game by itself, and that is a good part of the
  classic library.

  It is not a full Kickstart, though. It has no AmigaDOS, so anything that
  relies on dos.library - Workbench disks, hard-disk installs, WHDLoad - needs
  a real ROM. That one AmiJa cannot supply: Kickstart is still under copyright.
  Two lawful ways to get it are to buy Amiga Forever from Cloanto
  (amigaforever.com), which includes every version, or to dump the chip out of
  an Amiga you own.

  Once you have the file, press F12 and drop it into "Kickstart 1.3". If you
  also play hard-disk or WHDLoad games, add a Kickstart 3.1 in the box below
  it: AmiJa picks whichever the game needs. Press OK and the machine boots.

  ---------------------------------------------------------------------------
  2.1   FILES AND FOLDERS
  ---------------------------------------------------------------------------

  Everything is resolved relative to AmiJa's HOME: the folder that holds the
  program itself - AmiJa.exe, bin/AmiJa, AmiJa.app or AmiJa.jar, depending on
  how you got it. It does not matter which directory you start it from, or
  whether you launch it from a shortcut, a menu entry or the Dock.

  (Started some other way, with no such folder to speak of - from an IDE, or
  from "mvn exec" - AmiJa falls back to the working directory instead.)

  Because AmiJa keeps everything next to itself, its home must be a folder you
  can WRITE to. Extract the archive into your own space rather than into
  Program Files, /opt or /Applications, or nothing will be saved.

    amiga.properties     the configuration file. Searched in the home folder
                         first, then on the classpath; if it is missing
                         altogether a default one is created.
    shaders/             RetroArch shader presets (*.glslp) offered in the
                         Shader drop-down.
    blurs/               the companion shader pack, used by presets that ask
                         for a blur pass.
    screenshots/         PNG files written by "Take Screenshot".
    savestate/           state1.a5s (the single save-state slot) and
                         state1.png (a thumbnail of the saved screen).
    whdload-saves/       persistent WHDSaves: volume for WHDLoad games.
    floppysounds/        the drive samples behind the mechanical noise. Ships
                         filled; replace them with your own if you like, or
                         empty the folder to silence the drives.

  One more folder holds material AmiJa is not allowed to ship, so it arrives
  empty and the features that read it stay quietly switched off until you fill
  it. The "Optional files" section of the popup (3.11) downloads it for you
  from its official site:

    whdload/             the WHDLoad system files, in WHDLoad_files/, plus the
                         relocation tables (.RTB) some installs need.

  ---------------------------------------------------------------------------
  2.2   KEYBOARD AND MOUSE AT A GLANCE
  ---------------------------------------------------------------------------

    F12                     opens the configuration popup and pauses the
                            machine. (Because F12 is taken, the Amiga HELP key
                            lives on Home - see below.)
    Left / Right Alt        the two Amiga keys. Windows keys work as well.
    Ctrl + Amiga + Amiga    the Amiga hard reset, exactly as on real hardware:
                            hold all three, the machine reboots when you let go.
    Page Up / Page Down     left / right Amiga Alt (these give @ # [ ] { } on
                            the Italian keymap).
    Home                    the Amiga HELP key.

    Left mouse button       clicking in the window captures the mouse: the host
                            pointer disappears and drives the Amiga pointer
                            without ever hitting the edge of the screen.
    Middle mouse button     releases the capture (losing window focus releases
                            it too).
    Right mouse button      the Amiga right button.

    Drag and drop           dropping a disk image onto the window inserts it.
                            The window is divided into four quadrants, one per
                            drive: drop on the top-left for DF0, top-right for
                            DF1, and so on. The path is remembered in the
                            configuration, so the popup shows it afterwards.


===============================================================================
 3.  THE F12 POPUP
===============================================================================

  Pressing F12 pauses emulation, releases the mouse and opens the configuration
  window: a column of sections, followed by a bar of action buttons.

  You never see all of them at once, because two of the sections are two ways
  of saying the same thing. With "Expert mode" off - the way AmiJa starts - the
  media you load live in a single "Drives" list (3.3) and the machine is built
  around them. Tick "Expert mode" and that list is replaced by the three
  sections that set each kind of drive by hand: Floppy drives (3.4), Hard disks
  (3.5) and WHDLoad (3.6).

  So the popup shows, in this order:

    System (3.2)          the machine: ROM, memory, chipset, video standard
    Drives (3.3)          ... in automatic mode
      or Floppy drives, Hard disks, WHDLoad (3.4 - 3.6) in expert mode
    Saved state (3.7)     the save slot, with a thumbnail of what is in it
    Game ports (3.8)      what is plugged into the two Amiga ports
    Remote play (3.9)     hosting a second player, or joining one
    Audio / Video (3.10)  renderer, shader, window, LEDs, drive sounds
    GUI                   language and interface scale, described under 3.2
    Optional files (3.11) the downloader for the files AmiJa may not ship;
                          it disappears once everything is installed

  A machine you are only watching has less to configure: joining someone else's
  session (3.9) hides System, the drives and the save slot, because on that
  computer there is no emulated Amiga to set up - what is left is your own
  picture, sound and controls.

  ---------------------------------------------------------------------------
  3.1   HOW TO READ THIS CHAPTER
  ---------------------------------------------------------------------------

  Every control is listed with the amiga.properties key it writes, the values it
  accepts, and when the change becomes effective:

    LIVE       applied immediately when you press OK, machine keeps running.
    RESTART    needs the emulated machine to be rebuilt. You do not have to do
               it by hand: pressing OK after changing one of these settings
               performs the cold restart for you (the alternative is to press
               the Restart button).
    RELAUNCH   needs the whole application to restart. AmiJa relaunches itself
               automatically; only the interface scale is in this class,
               because the look and feel reads it once at start-up.
    BOOT       read when the machine is built, so it applies at the next
               Restart (or at the next launch).

  Two keys - ESC cancels the popup, ENTER confirms it. Note that the file
  browsers behind the "..." buttons save the directory you last visited
  immediately, even if you then press Cancel.

  ---------------------------------------------------------------------------
  3.2   SYSTEM
  ---------------------------------------------------------------------------

  The last two entries of this section - Language and Interface scale - live in
  a box of their own at the bottom of the popup, labelled "GUI": they are the
  settings that describe AmiJa itself rather than the machine it emulates.

  +-------------------------------------------------------------------------+
  |  [ ] Expert mode                                           auto.enabled  |
  +-------------------------------------------------------------------------+
     The switch between the two ways of using AmiJa, and the first thing to
     understand about this popup.

     Left OFF - the default - you supply the games and AmiJa builds the machine
     around them. Load a floppy image and you get a stock A500 with Kickstart
     1.3; load a hard disk image or a WHDLoad archive and you get the expanded
     machine those need, with Kickstart 3.1, 1 MB of Chip RAM, 8 MB of Fast RAM
     and the ECS chipset. Even the video standard follows the file: a name
     containing "NTSC" or "(USA)" - the convention TOSEC, No-Intro and WHDLoad
     use - selects NTSC, everything else PAL. The memory, chipset and video
     rows below then show what was deduced and cannot be edited.

     Ticked, nothing is deduced: every setting is yours, as on a real Amiga,
     and the drive list is replaced by the three per-kind sections (3.4 - 3.6).

     Your manual choices are not lost while the automatic mode is on. They stay
     in the file exactly as you left them and come back into force the moment
     you tick this box. The values the automatic mode uses are themselves
     properties you can change - see 4.2.

     Note the polarity: the box is called "Expert mode", the property is called
     auto.enabled, and they are opposites. Ticking the box writes false.
     Values . . . . . true / false (default true = automatic)
     Applies . . . . . BOOT

  +-------------------------------------------------------------------------+
  |  Kickstart 1.3 (.rom):                            auto.kickstart13.path  |
  |  Kickstart 3.1 (.rom):                            auto.kickstart31.path  |
  +-------------------------------------------------------------------------+
     The two ROMs the automatic mode chooses between: the 1.3 for plain floppy
     games, which is what almost all of them expect, and the 3.1 for anything
     involving a hard disk or WHDLoad, where a 1.x Kickstart usually is not
     enough. You set them once and never think about them again.

     Only one of the two is required. If the profile AmiJa wants is empty it
     falls back to the other, and then to the expert-mode kickstart.path below
     - so a configuration carried over from an older AmiJa, which only had that
     one key, still boots. With both empty the built-in ROM takes over (2).

     The "..." buttons open a browser filtered on *.rom, which remembers its
     folder in chooser.rom.lastDirectory.
     Values . . . . . absolute path or empty      Applies . . . BOOT

  +-------------------------------------------------------------------------+
  |  Kickstart (.rom):                                        kickstart.path |
  +-------------------------------------------------------------------------+
     The single ROM used in expert mode, mapped at $FC0000-$FFFFFF. A 256 KB
     image is the usual case (Kickstart 1.3 rev 34.5 is the reference; 2.0/3.1
     images work for hard-disk and WHDLoad setups), but any power-of-two image
     up to 512 KB is accepted and mirrored into the socket as the real hardware
     would. Real dumps carrying loader headers, appended tails or duplicated
     halves are normalised on the way in; a file that turns out to be a CDTV
     extended ROM, or an image meant to be relocated into RAM by ReKick, is
     refused with an explanation of what it actually is.
     Values . . . . . absolute path      Applies . . . BOOT

  +-------------------------------------------------------------------------+
  |  Chip RAM:                                                   chipram.kb  |
  +-------------------------------------------------------------------------+
     Memory shared by CPU and custom chips, from $000000 upwards. 512 KB is the
     stock A500; 1 MB or 2 MB is what most WHDLoad titles ask for.
     Values . . . . . 256 / 512 / 1024 / 2048 (KB)
     Applies . . . . . BOOT

  +-------------------------------------------------------------------------+
  |  Slow RAM:                                                   slowram.kb  |
  +-------------------------------------------------------------------------+
     The classic "trapdoor" expansion at $C00000, seen by the system as slow
     Fast RAM. 512 KB gives you the familiar 1 MB A500.
     Values . . . . . 0 / 512 / 1024 / 1536 / 1792 (KB), 0 = none
     Applies . . . . . BOOT

  +-------------------------------------------------------------------------+
  |  Fast RAM:                                                   fastram.kb  |
  +-------------------------------------------------------------------------+
     True Fast RAM on a Zorro II AutoConfig board - no chip-bus contention, so
     the CPU runs at full speed there. Required by many hard-disk and WHDLoad
     installations.
     Values . . . . . 0 / 512 / 1024 / 2048 / 4096 / 8192 (KB), 0 = none
     Applies . . . . . BOOT

  +-------------------------------------------------------------------------+
  |  Language:                                                  ui.language  |
  +-------------------------------------------------------------------------+
     Language of the emulator's own interface (menus, dialogs, messages). It
     has no effect on the emulated Amiga, whose keymap and language come from
     the Kickstart and from Workbench.
     Values . . . . . English -> en, Italiano -> it
     Applies . . . . . BOOT

  +-------------------------------------------------------------------------+
  |  Interface scale:                                              ui.scale  |
  +-------------------------------------------------------------------------+
     Size of AmiJa's own windows - this popup, the dialogs, the file browser.
     1 is the native size, 1.5 makes everything half as big again, 2 doubles
     it. Useful on a high-resolution screen, where a native-size popup can be
     uncomfortably small.

     Unlike "Integer scaling" (3.10) this one accepts fractional values: the
     interface is not an emulated picture, so a soft edge in a dialog costs
     nothing. Text does not blur either - the font is redrawn at the larger
     size, not stretched.

     It never touches the emulated window, which keeps the size set by the
     integer scaling factor. The two settings are completely independent.

     AmiJa reads this once, when it starts, so changing it relaunches the
     application. It does not read the scale factor of your desktop: if you
     want a bigger interface, ask for it here.

     The popup will not grow past the screen: if the chosen scale would make it
     taller than the desktop, it stops there and its content scrolls.
     Values . . . . . 1, 1.25, 1.5, 1.75, 2, 2.5, 3 (shown as a percentage in
                      the popup; any value from 1 to 4 is accepted in the file)
     Applies . . . . . RELAUNCH

  +-------------------------------------------------------------------------+
  |  Video mode:                                                 video.mode  |
  +-------------------------------------------------------------------------+
     Television standard of the emulated machine: PAL (50 Hz, 312 lines) or
     NTSC (60 Hz, 262 lines). It sets the colour clock, the number of raster
     lines per frame and the Agnus ID the Kickstart reads.
     Values . . . . . PAL / NTSC        Applies . . . RESTART (automatic on OK)

  +-------------------------------------------------------------------------+
  |  Chipset:                                                       chipset  |
  +-------------------------------------------------------------------------+
     Custom chip generation. OCS is the original A500; ECS adds the enhanced
     Agnus/Denise and their extra registers (BEAMCON0, DIWHIGH, BPLCON3,
     productivity modes) and is what ECS-only titles expect.
     Values . . . . . OCS / ECS         Applies . . . RESTART (automatic on OK)

  ---------------------------------------------------------------------------
  3.3   DRIVES (AUTOMATIC MODE)
  ---------------------------------------------------------------------------

  With "Expert mode" off, everything you load lives in one list. There is no
  drive to pick and no format to declare: you add files, AmiJa works out what
  each one is and where it belongs, and the machine is built to match.

  +-------------------------------------------------------------------------+
  |  Drive 1:                        "..."                                   |
  |  Drive 2:                        "..."                                   |
  +-------------------------------------------------------------------------+
     One row per file, plus an empty one at the bottom waiting for the next.
     Pick a file - or drag it onto the window - and the row renames itself to
     where the file ended up:

       DF0: ... DF3:          floppy images (.adf, .ipf, .zip), in the order
                              you added them. DF0 is the one the Amiga boots
                              from
       Hard drive master:     the first .hdf image
       Hard drive slave:      the second
       WHDLoad:               a .lha or .lzh game archive

     The limits are the machine's own: four floppy drives, two hard disks, and
     a WHDLoad archive that cannot sit next to a hard disk image because both
     want to be the boot volume. A file that does not fit is refused with the
     reason; a file of a kind AmiJa does not recognise is refused as such.

     The small button at the end of a row removes that entry. The browser
     remembers its folder in chooser.media.lastDirectory.

     Underneath, these rows write exactly the same properties expert mode does
     - drive.dfN.disk, hd.master.disk, whdload.file and the rest. The two modes
     describe one machine; they differ in who decides the layout.
     Applies . . . . . LIVE for floppies, BOOT for hard disks and WHDLoad

  ---------------------------------------------------------------------------
  3.4   FLOPPY DRIVES (EXPERT MODE)
  ---------------------------------------------------------------------------

  One row per drive, DF0 to DF3. Each row has four controls: the connection
  checkbox, the disk path, and three small buttons - browse, write protect and
  eject. The path field and the buttons are greyed out while the drive is not
  connected.

  +-------------------------------------------------------------------------+
  |  [x] DFn connected                                 drive.dfN.enabled     |
  +-------------------------------------------------------------------------+
     Whether the drive physically exists. A disconnected drive reports no ID
     to the system and holds no disk. DF0 and DF1 are connected by default.
     Values . . . . . true / false      Applies . . . LIVE

  +-------------------------------------------------------------------------+
  |  <path>                          "..."               drive.dfN.disk     |
  +-------------------------------------------------------------------------+
     Absolute path of the image inserted in the drive; empty means no disk.
     Accepted formats:

       .adf   plain sector image, the common case
       .ipf   flux-level image of an original disk, including copy protection
              (Rob Northen Copylock, variable density, long tracks, ...)
       .zip   a compressed disk image; if the archive contains several disks
              it is treated as a set - the first one goes into DF0 and the
              others fill the free connected drives automatically, addressed
              as <archive>.zip!<n>. Disks from a ZIP are always write
              protected.

     Applies . . . . . LIVE. Replacing a disk in a running machine ejects the
     old one, waits about a second and a half so the Kickstart notices the
     change, and then inserts the new one - exactly like swapping disks for
     real. The browser remembers its directory in chooser.floppy.lastDirectory.

  +-------------------------------------------------------------------------+
  |  padlock button                                    drive.dfN.readonly    |
  +-------------------------------------------------------------------------+
     Write protection. Closed padlock = the disk is mounted read-only and the
     emulated machine sees the write-protect tab closed; open padlock = writes
     go back into the image file. Keep it closed for anything you care about.
     Values . . . . . true / false      Applies . . . LIVE

  +-------------------------------------------------------------------------+
  |  eject button                                                           |
  +-------------------------------------------------------------------------+
     Clears the path field. The disk is actually ejected when you press OK.

  ---------------------------------------------------------------------------
  3.5   HARD DISKS (EXPERT MODE)
  ---------------------------------------------------------------------------

  Two units, master and slave, mounted through a Zorro II AutoConfig controller
  whose boot ROM carries the filesystem (OFS/FFS). This is how games installed
  on an .hdf image are booted.

  +-------------------------------------------------------------------------+
  |  [x] Master (.hdf)                                  hd.master.enabled    |
  |  [x] Slave  (.hdf)                                  hd.slave.enabled     |
  +-------------------------------------------------------------------------+
     Whether the unit is present.
     Values . . . . . true / false      Applies . . . BOOT

  +-------------------------------------------------------------------------+
  |  <path>                          "..."              hd.master.disk       |
  |                                                     hd.slave.disk        |
  +-------------------------------------------------------------------------+
     Absolute path of the .hdf image; empty means no disk. The browser
     remembers its directory in chooser.hdf.lastDirectory.
     Applies . . . . . BOOT

  +-------------------------------------------------------------------------+
  |  padlock button                                     hd.master.readonly   |
  |                                                     hd.slave.readonly    |
  +-------------------------------------------------------------------------+
     Mount the image read-only. Unlike floppies, hard disks default to
     writable - saved games and preferences need it.
     Values . . . . . true / false      Applies . . . BOOT

  ---------------------------------------------------------------------------
  3.6   WHDLOAD (EXPERT MODE)
  ---------------------------------------------------------------------------

  +-------------------------------------------------------------------------+
  |  [x] Auto-run WHDLoad archive (.lha)                 whdload.enabled     |
  |  <path>                          "..."               whdload.file        |
  +-------------------------------------------------------------------------+
     Point AmiJa at a WHDLoad archive and it does the rest: the .lha/.lzh is
     extracted, packed on the fly into a bootable FFS hard disk together with
     the WHDLoad system, and started - no installation, no Workbench setup.
     This is the same approach as the WHDLoad support in RetroArch/PUAE.

     Saved games are kept outside the throw-away disk, in whdload-saves/, so
     they survive across sessions. The WHDLoad preferences themselves
     (SplashDelay, ButtonWait, NoFilter and friends) are not in this popup;
     they live in the whdload.prefs.* section of amiga.properties - see 4.6.

     A word on requirements: most WHDLoad titles want more memory than a stock
     A500. If a game refuses to start, raise Chip RAM to 1 MB and give it a few
     megabytes of Fast RAM.

     Values . . . . . true / false, absolute path to .lha or .lzh
     Applies . . . . . BOOT
     The browser remembers its directory in chooser.whdload.lastDirectory.

  ---------------------------------------------------------------------------
  3.7   SAVED STATE
  ---------------------------------------------------------------------------

  There is one slot, savestate/state1.a5s, and the section shows what is in it:
  a thumbnail of the screen as it was, and the date it was taken, or "No state
  saved yet" if you have never used it.

     Save State        Freezes the whole machine into the slot - memory, chips,
                       CPU, the disks that were inserted - so you can come back
                       to this exact moment. It replaces whatever was there,
                       picture and all.

     Load State        Puts the machine back to the slot and throws away what
                       is running now.

  The slot also carries the machine setup it was saved with. That is what makes
  it survive your changing things afterwards: load a state taken on a different
  configuration and AmiJa puts that configuration back, rebuilds the machine
  and then restores the state, telling you it has done so. A state written by
  an older AmiJa whose format no longer matches is refused with the reason,
  rather than restored half-way.

  ---------------------------------------------------------------------------
  3.8   GAME PORTS
  ---------------------------------------------------------------------------

  +-------------------------------------------------------------------------+
  |  Port 0:                                          input.port0.device     |
  |  Port 1:                                          input.port1.device     |
  +-------------------------------------------------------------------------+
     What is plugged into each of the two Amiga game ports. Port 0 is the mouse
     port (JOY0DAT), the one Workbench and point-and-click games want; Port 1
     is the joystick port (JOY1DAT), which is what nearly every game reads.

       Mouse . . . . . . . . the host mouse                  -> mouse
       Joystick (real) . . . a physical joystick or gamepad,
                             read through GLFW               -> joystick-real
       Joystick (keyboard) . a joystick emulated on the host
                             keyboard                        -> joystick-keyboard
       Empty . . . . . . . . nothing connected               -> none

     Choosing "Joystick (keyboard)" makes a "..." button appear next to the
     drop-down, which opens the key mapping for that port (see 3.12.1). Both
     ports can use the keyboard at the same time, because each one has its own
     set of keys.

     During a remote-play session (3.9) you can only set the port that is
     yours; the other one belongs to the player at the other end, and the
     section says so in place of the drop-down.
     Applies . . . . . LIVE

  ---------------------------------------------------------------------------
  3.9   REMOTE PLAY
  ---------------------------------------------------------------------------

  Two people, two computers, one Amiga. The machine runs on the host's
  computer, which sends the picture and the sound over the network; the guest's
  computer emulates nothing at all - it shows what arrives and sends back the
  controls, which drive one of the two game ports of the host's machine.

  The consequence worth stating first: the guest needs neither a Kickstart nor
  a copy of the game. Whoever owns the disk hosts, and the other one just
  joins.

  The delay is paid by the guest alone - the host plays exactly as if nobody
  were connected. On a local network it adds about one frame and is not
  perceptible. Over a decent Internet connection within the same country it is
  around three frames: fine for a sports game or a two-player beat-'em-up,
  noticeable in a game of pure reflexes. On a poor link it is like playing with
  a bad joypad.

  A session is one guest at a time. The Amiga has two game ports and the host
  is using one of them.

  +-------------------------------------------------------------------------+
  |  Mode:               Off / Host / Join                                   |
  +-------------------------------------------------------------------------+
     Which side of the session you are on, and the only control always visible
     here: choosing one reveals that role's rows and hides the other's. It is
     not saved in amiga.properties - AmiJa always starts with no session, which
     is the only safe default for something that opens a listening port.

  HOSTING
  ..........................................................................

  Set Mode to "Host" and the rows below appear.

  +-------------------------------------------------------------------------+
  |  Port:                                                  remoteplay.port  |
  |  [x] Open the port on the router (UPnP)                 remoteplay.upnp  |
  +-------------------------------------------------------------------------+
     The port the other player connects to, used for both TCP (the session
     itself) and UDP (picture, sound and controls). One number for both, so
     there is a single thing to pass on and a single pair of rules for the
     router.

     UPnP asks the router to forward that port by itself, and withdraws the
     forwarding when you stop hosting. Nothing is asked of the router while
     "Local network only" is on, since nobody from outside would be admitted
     anyway.
     Values . . . . . 1-65535 (default 7788) / true / false (default true)
     Applies . . . . . when you start hosting

  +-------------------------------------------------------------------------+
  |  Security:  [x] Local network only                  remoteplay.lan.only  |
  +-------------------------------------------------------------------------+
     Refuses guests from outside your own network. On by default, deliberately:
     a port listening on the open Internet is something you turn on knowingly,
     not something you end up with because you once tried this feature at home.
     Values . . . . . true / false (default true)
     Applies . . . . . when you start hosting

  +-------------------------------------------------------------------------+
  |  Session:            [ Start hosting ]                                   |
  +-------------------------------------------------------------------------+
     Opens the port and waits. Your machine carries on exactly as it was -
     hosting adds a guest, it does not change how you play - and the popup
     stays open so you can read what happens next. The same button then reads
     "Stop hosting", which closes the session and tells the guest why.

  +-------------------------------------------------------------------------+
  |  Address:            192.168.1.20:7788               [ Copy ]            |
  |  Internet:           93.45.12.7:7788                 [ Copy ]            |
  |  Join code:          K7M2-Q4XZ                       [ Copy ]            |
  +-------------------------------------------------------------------------+
     What to pass to the other player, filled in once you are listening.

     "Address" is where to reach you on your own network. "Internet" is where
     to reach you from outside, and appears only once the router has confirmed
     the forwarding; when that could not be done, the line carries the reason
     instead of an address nobody could use - see the troubleshooting list
     below.

     The join code is the password of this session. It is generated afresh
     every time you start hosting, it is never stored in amiga.properties, and
     it never travels over the network in the clear: both ends prove they know
     it, and the keys that encrypt the session are derived from it. Eight
     characters written to be read out loud - case is ignored, and O/0 and I/1
     count as the same character.

  +-------------------------------------------------------------------------+
  |  Guest uses:  Port 1                            remoteplay.guest.port    |
  |  [x] Share the keyboard                     remoteplay.guest.keyboard    |
  |  [ ] The guest may reset                  remoteplay.guest.allowreset    |
  +-------------------------------------------------------------------------+
     What the guest is allowed to do on your machine. All three are decided
     here and enforced here, so they hold whatever the other end sends.

     "Guest uses" hands over one of the two game ports - Port 1, the joystick
     one, by default, which leaves you Port 0 if you play with the mouse. You
     choose the port and only the port: what gets plugged into it, mouse or
     joystick or which keys, is the guest's own choice, made in the popup on
     their computer and changeable mid-game.

     "Share the keyboard" lets the guest type on your machine. They still
     cannot open your popup, and F12 on their computer opens their own.

     "The guest may reset" allows CTRL+Amiga+Amiga from the other end to reboot
     YOUR machine. Off by default, and worth leaving off.
     Values . . . . . 0 / 1 (default 1), true / false, true / false
     Applies . . . . . at the next guest connection

  +-------------------------------------------------------------------------+
  |  Audio:      Compressed (355 kbit/s)          remoteplay.audio.mode      |
  +-------------------------------------------------------------------------+
     What the guest hears, and how much bandwidth it costs.

       Compressed (355 kbit/s)     IMA-ADPCM        -> adpcm
       Uncompressed (1.4 Mbit/s)   plain 16-bit PCM -> pcm16
       Off                         no sound sent    -> off

     Compressed is the default and is indistinguishable by ear; it matters
     because the picture itself only costs between 0 and 5 Mbit/s, so
     uncompressed sound would be a third of the whole stream. Uncompressed is
     bit-exact and makes sense on a local network.

     The audio filter - the one the power LED shows - is applied by the host.
     The guest's own setting has no effect on what they hear.
     Values . . . . . adpcm / pcm16 / off (default adpcm)
     Applies . . . . . at the next guest connection

  JOINING
  ..........................................................................

  Set Mode to "Join" instead, and give the two things the host read out to you.

  +-------------------------------------------------------------------------+
  |  Host address:       192.168.1.20:7788          remoteplay.last.host     |
  |  Join code:          K7M2-Q4XZ                                           |
  +-------------------------------------------------------------------------+
     The address in the form address:port, and the code. The address you last
     used is remembered for next time; the code never is.

  +-------------------------------------------------------------------------+
  |  Session:            [ Connect ]                                         |
  +-------------------------------------------------------------------------+
     Starts connecting and leaves the popup open, so a failure has somewhere to
     be explained: watch the Status line. The session really does open at this
     point - the picture starts arriving behind the popup - but your machine is
     still your machine.

     It stops being one when you confirm with OK. From then on this computer
     emulates nothing: it shows what arrives and sends back your controls, and
     the popup, if you open it again, offers only what still applies here -
     your picture, your sound, your controls. "Disconnect" puts your own Amiga
     back.

  +-------------------------------------------------------------------------+
  |  Status:             Guest connected - 1500 frames sent, 2 skipped       |
  +-------------------------------------------------------------------------+
     Always visible, in both modes, and refreshing on its own while the popup
     is open: whether anyone is connected, how an attempt is going, and why the
     last one failed.

  WHEN IT DOES NOT WORK
  ..........................................................................

  The Status and Internet lines are written to be read literally. The cases you
  are most likely to meet:

    "Your provider does not give you a public address (CGNAT)"
        Your connection shares one address between many customers, which is
        common on mobile and on some fibre contracts. Nothing can reach you
        from the Internet, and no setting fixes it. Let the other player host.

    "No router answered" / "The router refused to open the port"
        UPnP is off in the router, or not offered. Turn it on, or forward the
        port to this computer by hand.

    "port opened by the router. If nobody can get in, it is the firewall"
        The forwarding is in place, so what is left is the computer's own
        firewall. Windows asks for permission the first time AmiJa listens; if
        that was refused, incoming traffic is dropped no matter how right the
        router is.

    "nothing is listening on that port" / "that address does not exist"
        As a guest: check the address and port you were given, and that the
        host has actually pressed "Start hosting".

    "no answer - address, port or firewall"
        The address exists but nothing came back. Over the Internet this is
        usually the host's firewall or a missing forwarding.

    "the host only accepts players on its own local network"
        The host still has "Local network only" ticked.

    "wrong join code"
        The code is regenerated every time hosting starts, so an old one will
        not do. Have it read out again.

    "the two machines run different versions of AmiJa"
        Both ends must run the same version.

  ---------------------------------------------------------------------------
  3.10   AUDIO / VIDEO
  ---------------------------------------------------------------------------

  +-------------------------------------------------------------------------+
  |  Rendering:                                             video.renderer   |
  +-------------------------------------------------------------------------+
     How the emulated framebuffer reaches the screen. Software uses Java2D and
     is the default; OpenGL presents the frame through the GPU inside the same
     window and is what makes shaders available. On this hardware the software
     path is at least as fast, so pick OpenGL when you want a CRT look rather
     than for speed.
     Values . . . . . Software -> software, OpenGL -> opengl
     Applies . . . . . RESTART (automatic on OK)

  +-------------------------------------------------------------------------+
  |  Shader:                                                  video.shader   |
  +-------------------------------------------------------------------------+
     RetroArch shader preset applied to the picture - scanlines, aperture
     grille, curvature, and so on. The drop-down lists the *.glslp files found
     in the shaders/ folder, plus "None" for a clean passthrough. Available
     only with the OpenGL renderer.

     The "..." button next to it opens the shader's own parameters (3.12.2).
     It is enabled only for the shader that is currently applied, so that what
     you tweak is what you see.
     Values . . . . . preset name without extension, or none
     Applies . . . . . LIVE

  +-------------------------------------------------------------------------+
  |  Window mode:                                         video.windowMode   |
  +-------------------------------------------------------------------------+
     Windowed . . . . . . . . . . normal resizable window     -> windowed
     Fullscreen . . . . . . . . . exclusive full screen       -> fullscreen
     Borderless windowed  . . . . a window without decoration
                                  covering the whole screen   -> borderless-windowed
     Applies . . . . . RESTART (automatic on OK)

  +-------------------------------------------------------------------------+
  |  Monitor:                                                video.monitor   |
  +-------------------------------------------------------------------------+
     Which screen the emulator opens on: 0 is the primary one, 1, 2, ... the
     other connected monitors. A configured index that no longer exists falls
     back to the primary screen, and stays selectable so it is not lost when
     you unplug a monitor.
     Values . . . . . 0, 1, 2, ...      Applies . . . RESTART (automatic on OK)

  +-------------------------------------------------------------------------+
  |  Integer scaling:                                video.integerScaling    |
  +-------------------------------------------------------------------------+
     Whole-number magnification of the emulated picture: 1 is the native size,
     2 doubles it, 3 triples it. Integer factors keep pixels square and
     identical, which is why there is no 1.5 here - each Amiga pixel becomes an
     exact block of screen pixels, with no interpolation and nothing blurred.

     It magnifies the emulated window and nothing else. To make the popup and
     the other AmiJa windows bigger, use "Interface scale" (3.2) instead; the
     two are independent and either can be left at 1.

     A window cannot be larger than the screen: Windows will not allow it, and
     neither will most desktops. PAL with overscan at 2x asks for 1448x1152, so
     on a 1920x1080 screen it does not fit and the picture ends up cropped at
     the bottom. If that happens, either turn overscan off (640x512, so 1280x1024
     at 2x) or go back to 1.
     Values . . . . . 1, 2, 3, ...      Applies . . . RESTART (automatic on OK)

  +-------------------------------------------------------------------------+
  |  [x] Enable overscan                            video.overscan.enabled   |
  +-------------------------------------------------------------------------+
     Show the whole video area the Amiga generates, borders included, instead
     of cropping to the standard active area. Some games draw right into the
     overscan region; others leave it empty. Window size follows:

       overscan on    PAL 724x576     NTSC 724x480
       overscan off   PAL 640x512     NTSC 640x400

     Values . . . . . true / false      Applies . . . RESTART (automatic on OK)

  +-------------------------------------------------------------------------+
  |  [x] Show power/drive LED panel                        leds.visible      |
  +-------------------------------------------------------------------------+
     The strip of LEDs under the picture: power (which on the Amiga also
     signals the audio filter state), the four floppy drives and the hard
     disks, each lighting up on access just like the real machine.
     Values . . . . . true / false      Applies . . . BOOT

  +-------------------------------------------------------------------------+
  |  Floppy sound volume (0 = mute):               floppy.sound.volume       |
  +-------------------------------------------------------------------------+
     Volume of the mechanical drive sounds - the seek clicks, the motor, the
     insertion clunk. 0 is silence, 1 is the quietest audible level, and each
     step adds about 6 dB up to 10. It does not affect the Amiga's own audio.
     The samples themselves live in floppysounds/ and can be replaced with
     your own - see the readme.txt in that folder.
     Values . . . . . 0 to 10           Applies . . . LIVE

  3.11   OPTIONAL FILES
  ---------------------------------------------------------------------------

  +-------------------------------------------------------------------------+
  |  WHDLoad, relocation tables                    [ Download... ]           |
  +-------------------------------------------------------------------------+
     Two packages AmiJa is not allowed to redistribute, and an assistant that
     fetches them for you:

       WHDLoad               the loader itself, required before any .lha game
                             archive can be started, unpacked into whdload/
       Relocation tables     the .RTB files WHDLoad installs need when they
                             emulate a different Kickstart

     AmiJa redistributes nothing: each file travels from the rights holder's
     own server to your disk, exactly as if you had clicked the link in a

  ---------------------------------------------------------------------------
  3.12   SUB-DIALOGS ("..." BUTTONS)
  ---------------------------------------------------------------------------

  3.12.1   KEYBOARD JOYSTICK KEYS
  ..........................................................................

     Opened by the "..." next to a port set to "Joystick (keyboard)". One row
     per function - Up, Down, Right, Left, Fire: click the button showing the
     current key, then press the key you want. ESC cancels the capture, which
     is why ESC itself cannot be assigned.

     A key can only serve one function, on either port, so the two joysticks
     never fight over the same key; if you pick one that is taken, the dialog
     tells you which function and which port already owns it. "Reset to
     defaults" restores that port's original keys.

       Port 0 defaults    W A S D + right Ctrl
       Port 1 defaults    arrow keys + left Ctrl

     Properties . . . input.port0.joystick.up
                      input.port0.joystick.down
                      input.port0.joystick.right
                      input.port0.joystick.left
                      input.port0.joystick.fire
                      input.port1.joystick.up   ... and the same five for port 1

     A value is the name of the java.awt.event.KeyEvent VK_ constant without
     the prefix - W, UP, SPACE, NUMPAD5 - and for keys that exist twice on the
     keyboard the position is appended: CONTROL:LEFT, CONTROL:RIGHT,
     SHIFT:LEFT, and so on.
     Applies . . . . . LIVE

  3.12.2   SHADER PARAMETERS
  ..........................................................................

     Opened by the "..." next to the Shader drop-down. Every "#pragma
     parameter" the preset declares - curvature, scanline weight, mask
     strength, brightness - gets a slider. Moving it changes the picture
     immediately, so you can dial the look in while watching it.

     On close the values are written next to the preset as <preset>.params, so
     they are still there next time. A preset that declares no parameters
     simply says so.

  ---------------------------------------------------------------------------
  3.13   THE BUTTON BAR
  ---------------------------------------------------------------------------

     About             Which AmiJa this is: version, author and the address of
                       the project page. It changes nothing.

     Take Screenshot   Saves the game window - not the popup - as
                       screenshots/screenshot_<date>_<time>.png. Works with
                       both renderers.

     Soft Reset        Saves the configuration and resets the CPU, leaving
                       memory contents alone - the equivalent of the reset
                       vector, not of a power cycle.

     Restart           Saves the configuration and rebuilds the whole machine
                       from scratch, as if you had turned it off and on again.
                       This is how ROM, RAM, chipset, hard disk and WHDLoad
                       changes are applied.

     Quit              Closes the emulator, writing any pending hard-disk
                       changes out to their image files first. Configuration
                       edits not confirmed with OK are discarded.

     Cancel  (ESC)     Closes the popup and resumes emulation, discarding your
                       edits.

     OK      (ENTER)   Saves amiga.properties and applies everything: input and
                       floppy changes take effect immediately, and if you
                       touched a setting that needs a rebuilt machine or a new
                       window, the restart is performed for you.

 4.  PROPERTIES AVAILABLE ONLY IN amiga.properties
===============================================================================

  These settings have no control in the F12 popup - edit amiga.properties with
  a text editor while the emulator is closed, or the next save will overwrite
  your changes. Values in Windows paths keep their backslashes escaped
  (C:\\Amiga\\...) as in any Java properties file.

  ---------------------------------------------------------------------------
  4.1   FILE-BROWSER MEMORY
  ---------------------------------------------------------------------------

     chooser.media.lastDirectory      last folder used by the Drives list
     chooser.floppy.lastDirectory     ... by the disk browser
     chooser.rom.lastDirectory        ... by the Kickstart browser
     chooser.hdf.lastDirectory        ... by the hard disk browser
     chooser.whdload.lastDirectory    ... by the WHDLoad browser

     Housekeeping, maintained by AmiJa itself: each "..." browser reopens where
     you left it. They are written as soon as you pick a file, even if you then
     cancel the popup. Setting them by hand simply decides where the browsers
     start; an empty value means "no preference".
     Values . . . . . absolute path or empty

  ---------------------------------------------------------------------------
  4.2   AUTOMATIC-MODE PROFILES
  ---------------------------------------------------------------------------

  What the automatic mode (3.2) builds when it recognises what you loaded.
  There are two profiles - plain floppy, and the expanded machine a hard disk
  or WHDLoad needs - and these properties are the machine each one produces.
  Editing them keeps the automation and changes its result.

     Property                    Default   Applies to
     ----------------------------------------------------------------------
     auto.floppy.chipram.kb      512       a floppy-only setup: the stock
     auto.floppy.slowram.kb      512       A500 with the trapdoor expansion,
     auto.floppy.fastram.kb      0         which is what floppy games expect
     auto.floppy.chipset         OCS

     auto.hd.chipram.kb          1024      a hard disk or WHDLoad archive:
     auto.hd.slowram.kb          512       the expanded machine those
     auto.hd.fastram.kb          8192      installs ask for
     auto.hd.chipset             ECS

     The values accepted are the same as the corresponding System settings
     (3.2). Applies . . . BOOT

  Two more things the automatic mode decides are not properties, because they
  are read from what you loaded. The ROM comes from the two Kickstart paths of
  the System section, whichever suits the profile. The video standard is read
  from the file name: it is NTSC when the name of an active file contains
  "NTSC" or "(USA)", and PAL otherwise. Only the name is examined, not the
  folders above it, so a directory called "USA dumps" does not drag everything
  it holds to 60 Hz.

  ---------------------------------------------------------------------------
  4.3   REMOTE PLAY
  ---------------------------------------------------------------------------

  The rest of the remote-play settings are in the popup (3.9). These two are
  not:

     remoteplay.bind
        Which network interface to listen on when hosting - an IP address of
        this computer. Empty, the default, means all of them, which is what
        you want unless the machine has several networks and you mean to offer
        the session on one only.
        Values . . . . . local IP address or empty      Applies . . . when you
                                                        start hosting

     remoteplay.last.host
        The address you last joined, so the "Host address" field is already
        filled in next time. Housekeeping, maintained by AmiJa. The join code
        that goes with it is deliberately NOT saved: it is a session secret and
        the host generates a new one every time.
        Values . . . . . address:port or empty

  ---------------------------------------------------------------------------
  4.4   DIAGNOSTIC OVERLAYS
  ---------------------------------------------------------------------------

     overlay.fps.enabled
        Real frames per second in the bottom-left corner - the emulator's own
        speed, so you can tell whether it is keeping up with real time.
        Values . . . . . true / false (default false)      Applies . . . BOOT

     overlay.framecounter.enabled
        Emulated frame counter at the bottom centre. It counts Amiga frames
        regardless of how fast the emulator is running, which makes it a stable
        reference when you want to note down when something happens.
        Values . . . . . true / false (default false)      Applies . . . BOOT

     Both are off by default and cost nothing when off.

  ---------------------------------------------------------------------------
  4.5   BLITTER
  ---------------------------------------------------------------------------

     blitter.immediate
        When true, the blitter finishes every operation the instant BLTSIZE is
        written: no bus cycles are consumed and BBUSY is never seen high. This
        is deliberately not cycle-exact - it is a speed switch for games that
        sit in a loop polling the blitter, and it can break anything that
        relies on blitter timing. Leave it false unless you have a reason.
        Values . . . . . true / false (default false)      Applies . . . BOOT

  ---------------------------------------------------------------------------
  4.6   WHDLOAD PARAMETERS (WHDLoad.prefs)
  ---------------------------------------------------------------------------

  This section generates the S:WHDLoad.prefs file of the hard disk AmiJa builds
  for a WHDLoad archive. Do not edit that generated file - it is rewritten on
  every launch; change these properties instead. Command-line arguments and the
  slave's ToolTypes still take precedence over anything set here.

  Two kinds of entry. A flag is true/false: true emits the corresponding
  WHDLoad keyword, false omits it. A value is written as Keyword=value, and an
  empty value is left out entirely, letting WHDLoad use its own default.

    Property                        Default     What it does
    ----------------------------------------------------------------------
    whdload.prefs.buttonWait        false       Wait for a button press before
                                                starting (false = go straight in)
    whdload.prefs.configDelay       0           Time allowed to pick options in
                                                the splash window (1/50 s)
    whdload.prefs.splashDelay       250         How long the splash window stays
                                                up (1/50 s; 250 = 5 seconds).
                                                Set 0 to skip it
    whdload.prefs.readDelay         0           Delay after a disk read (1/50 s)
    whdload.prefs.writeDelay        0           Delay after a disk write (1/50 s)
    whdload.prefs.coreDumpPath      T:          Where coredumps are written
    whdload.prefs.savePath          WHDSaves:   Base directory for saved games
                                                (the persistent volume)
    whdload.prefs.noNetwork         true        Do not connect to the internet
    whdload.prefs.noWriteCache      false*      Disable the disk write cache
    whdload.prefs.noWriteInfo       false       Do not write .info files next to
                                                saved games
    whdload.prefs.chipNoCache       false       Make Chip memory non-cacheable
    whdload.prefs.fullChip          false       Save and restore the whole Chip
                                                memory
    whdload.prefs.noFlushMem        false       Do not free memory before loading
    whdload.prefs.noMemReverse      false       Do not allocate memory in reverse
                                                order
    whdload.prefs.preload           false       Buffer many data files up front
                                                at startup
    whdload.prefs.logBuffer         (empty)     Size of the logging buffer, e.g.
                                                $40000
    whdload.prefs.ntsc              false       Force NTSC
    whdload.prefs.pal               false       Force PAL
    whdload.prefs.noFilter          false       Disable the Amiga audio filter
    whdload.prefs.noAutoVec         false       Ignore unwanted autovector
                                                interrupts
    whdload.prefs.mmu               false       Use the MMU (68030 and above)
    whdload.prefs.quitKey           (empty)     Quit key, as a rawkey code
                                                (e.g. $5a)
    whdload.prefs.restartKey        (empty)     Restart key, rawkey code
    whdload.prefs.freezeKey         (empty)     Freeze key, rawkey code
    whdload.prefs.debugKey          (empty)     Debug key, rawkey code
    whdload.prefs.expert            false       Enable expert mode
    whdload.prefs.executeStartup    (empty)     Command run before the game, e.g.
                                                Execute S:WHDLoad-Startup
    whdload.prefs.executeCleanup    (empty)     Command run after the game

    (*) noWriteCache ships as true in the bundled amiga.properties, which is
        the safer setting; the built-in default is false.

    All of them apply at BOOT - the prefs file is generated while the WHDLoad
    hard disk is being built.
